## 步骤 1：修 182px 坐标系混用

已定位（第三轮实测，`zoom-probe.mjs` 可复跑）：
`getBoundingClientRect()` 返回**视觉 px**，`scrollTop` 吃**局部 px**，
`zoom:0.75` 下把前者赋给后者恒少滚 25%（实测 281/1126 = 24.96%）。`728 × 0.25 = 182`。

**本步只修换算，不动落点策略。** 恒顶部对齐留给后面的修复单。

```js
const z = host.getBoundingClientRect().height / host.offsetHeight || 1;  // 现算，不写死 0.75
sc.scrollTop += visualDelta / z;                                          // 视觉 → 局部
```

- `|| 1` 兜底：`offsetHeight === 0`（`display:none` / 首帧）会让 `z` 变 `Infinity`/`NaN`
- 测 `z` 要用**稳定的宿主元素**，不要用高度正在变的元素

### 预期效果（先说清，免得以为没修好）

截图那个 900px 窗口里，面板会**从 y=520 移到 y≈338**（真居中位置）。

但「上半边空一片」不会全消失 —— 居中本身会留 **272px** 上空。
那 182px 是这个 bug，剩下的 272px 是居中策略本身的问题，
**要等后面的恒顶部对齐**（届时上空变 24px）。本单不做。

### 单位规则注释，放 hook 顶部显眼处

```
// ⚠️ 这个文件里有两套坐标系，`#root { zoom: 0.75 }` 让它们不等价。
//
//   视觉 px（已含 zoom）：getBoundingClientRect()、window.innerHeight / innerWidth
//   局部 px（未含 zoom）：scrollTop、clientHeight、offsetHeight、scrollHeight、
//                        getComputedStyle()
//
// 两套【绝不能相减】。实测：把 rect 差值直接赋给 scrollTop 会恒定少滚 1-zoom
// = 25%（1126px 的目标少滚 281px）。这正是 #678 里那个 182px 偏移的成因
// （728 × 0.25 = 182）。
//
// 换算系数【现算，不要写死 0.75】：
//   const z = el.getBoundingClientRect().height / el.offsetHeight || 1
//   局部 = 视觉 / z
//
// 同理：`40vh` 的 computed 值不受 zoom 影响（恒为 0.4 × 真实视口高，局部 px），
// 但渲染出来要再乘 zoom —— 所以 max-h-[40vh] 实际只有 30vh。
// cqh 和 % 都躲不开这个乘数，实测三者渲染相同。换 CSS 单位无解，只能 JS 现算。
```

### 本步必加的回归断言

**`#root` 的 zoom 设成 `0.75` 和 `1` 两次跑定位，落点的「视觉 px 偏移」必须相同。**

这条专门钉住坐标系混用 —— 它保护的正是本步在修的东西，以后谁再混当场红。
（其余三条断言留给后面的修复单。）

### ⚠️ 41 处 JSX 必须脚本化变换，不许手敲

手敲这个量级的 JSX 会出解析错误 —— 已经发生过两次，成因都是**把注释插进三元表达式的
`(` 之后**。要求：

1. 写一个一次性变换脚本，**输出 diff 供审阅**，不直接落盘
2. **每个目标位置的匹配必须唯一** —— 命中 0 次或 ≥2 次就报错停下，不许猜
3. **注释一律放在语句之外**，不进三元分支、不进 JSX 属性列表
4. 变换后跑 `tsc -p tsconfig.app.json` + eslint，再逐文件肉眼过 diff
5. **计数断言**：实际改动的标记数 === 盘点清单里的数。差一个都要解释，不许"大概齐"
6. 脚本本身不进仓库（或放 `scripts/` 并在报告里说明），别留在源码树里
