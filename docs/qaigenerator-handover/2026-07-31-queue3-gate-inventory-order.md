## 为什么要先盘

铺 gate 的范围目前是**口头传下来的"六个表单"**，没有任何一次是从机制出发盘出来的。
用户点名了 "AI theme"、"AI topic" 两处，没人能确认它们在不在那六个表单的 USP 字段里。

**这一单的成功标准不是"确认六个表单"，是"证明不存在第七个"。**

### ⚠️ 最后那一列是关键，别当附注

同一个表单组件在不同模板下**可能渲染不同字段**。所以「表单接了 gate」**不等于**
「该模板下的 AI 面板都接了」。共用表单的每个模板都要独立核一遍它渲染出哪些面板 ——
否则会出现「组件清单 100% 覆盖，但某个模板照样没保护」。

## 一、发现方法：从机制搜，不从名字搜

不要以现有的六个表单为起点去核对。反过来：把所有"AI 产出 → 用户要拍板"的点全捞出来，
再看哪些落在已知范围内。六个角度都要跑，一个都不能省（任何单一角度都会漏）：

1. **调用点**：所有 `supabase.functions.invoke` / AI 请求发起处，逐个回溯它的返回值写进哪个 state
2. **组件名**：`AiPromptButton`、`AiAutofill`、`FBAdCoverPanel`、`TemplateGeneratePanel`
   —— 每一处使用点（不是定义点）都要列
3. **标识符**：`theme` / `topic` 相关的 state 与字段名。用户只知道 UI 文案叫 "AI theme"、
   "AI topic"，先把 UI 文案定位到真实标识符，再判断归属
4. **i18n key**：含 `ai` / `generate` / `suggest` / `recommend` 的 key，反查渲染它的组件
   —— 这条最容易捞出前五条漏掉的边角面板
5. **队列④ 的 11 个扣费路径**：花了钱的 AI 调用必然有用户要处置的产出，两张清单要对得上。
   对不上的差集就是漏点
6. **表单侧**：把 AI 结果写回表单字段的 setState（autofill 模式），这类没有"确认"按钮，
   但语义上仍是"AI 填了、用户得看一眼"

## 二、每一处要记录的字段

| 字段 | 说明 |
|---|---|
| 位置 | `file:line` |
| 触发 | 哪个按钮 / 自动触发 |
| 产出落点 | AI 结果写进哪个 state |
| active 条件 | 该处 gate 的激活判据（照 `previewUrl !== null` / `result !== null` 的形式写） |
| **挂载即非空？** | 见下方 ⚠️ |
| 是否需要 gate | 需要 / 不需要 / 禁区 |
| 已在范围 | 是 / **漏了** |
| 板子归属 | scope 按板子分，写出所属板子 |
| dim 标记数 | 该处需要几处标记 |

⚠️ **"挂载即非空"这一列必须逐处填，不许留空。**
#678 的对抗式复核已经发现 ①（`active: result !== null`）有个真风险：如果 result 能在挂载时
就非空（#676 的记录 tab 回填、草稿恢复），用户什么都没做就被红闪锁住。
这个坑在六个表单上会**重复六遍**。在盘点阶段一次性查清，比铺完再返工便宜得多。
每一处都要回答：这个 state 有没有任何"从历史/草稿/URL 参数恢复"的写入路径？

## 三、分类判据

- **需要 gate**：AI 出了东西，用户不处置就会带着 AI 的默认值进下一步（或进扣费流程）
- **不需要**：结果直接落进可自由编辑的输入框、没有"下一步"语义、不影响后续扣费
- **禁区**：`ImageEditor`（#590）、生成核心（`submitTask` 的 input / `buildSpec` /
  `pollTask` / `pollSegmentAsset` / `spendForAction` / 退款）、多租户 RLS（#588/#589）、
  `lazypackProduce.ts` 的 `VIDEO_T2V_MODEL`

**禁区里的点也要出现在清单上，标成"禁区"。** 不要静默省略 —— 省略了就没人知道那里
是"评估过、故意不做"还是"没看见"。

## 四、反向核对（防范围虚胖）

清单出来后回头核两件事：

1. 已知六个表单里，有没有"需要 gate 但不属于 USP 字段"的点？
   有的话单独标出来 —— 那是范围扩张，要我拍板才进单
2. **六个表单到底是哪六个？** 目前只有 `LazyPackForm`（已完成 9 处）、
   `MarketplaceVoiceGen`、`ThreeViewGenerator` 三个是点名的。另外三个是谁，明确写出来；
   如果凑不出六个，说明"六个"这个数本身是传错的，直接说

## 五、顺带校验已定方案

盘完后用真实数字校一遍既有决定，数不对就说：

- ~41 处 dim 标记 —— 按板子给出分解，总数对不上就报实际数
- scope 按板子分不按 gate 分 —— 有没有哪个板子跨了两个 gate，或哪个 gate 跨了两个板子
- 单值常量 `{...GATED}` 铺开 —— 有没有哪处的标记必须携带额外值（那就破了单值前提）
- 标记严格平级禁止嵌套 —— 盘点时若发现某处**结构上必然嵌套**（父子都该 dim），
  提前说。这是 opacity 相乘变 0.2 暗屏的来源，检测测试会当场红
- `[~=]` 选择器 —— 有没有哪处的属性值已被别的逻辑占用
